# Conversation and memory verification, October 2026

Recent installed-app conversations were reviewed privately. The defects included an obsolete owner-name preference overriding explicit corrections, denial of integrated speech capabilities, a repetitive training-cutoff explanation for selected-model questions, and inappropriate live-source routing. Owner conversations, names, credentials and transcripts are excluded from public examples and benchmark inputs.

Controller changes: selected-model questions answer directly from configuration; personal statements containing “today” do not trigger news search; an explicit rejection of the exact stored owner name removes that preference without guessing a replacement. Prompts distinguish quoted/background content from owner statements and current requests from personal recall. The changing local clock is placed after stable instructions to allow local prompt-prefix reuse.

Memory is still automatic SQLite retrieval, not continuous weight training or perfect recall. The exact command “Forget Wrongname from memory” runs a typed deletion before inference. It removes matching preferences, matching conversation turns and paired replies, clears derived summaries, and redacts affected tool records while preserving idempotency tombstones. Unrelated chats, notes, reminders and source documents remain. Model-generated deletion claims are replaced with verified acknowledgements or clear failures. Editing/deleting an explicit preference also selectively invalidates matching context. Deletion during another generation invalidates that turn so old text/audio cannot reappear. This is logical deletion, not guaranteed erasure from OS backups or historical WAL copies.

For a correction: search/inspect in Memory and edit the actual full message; the old paired answer and summary are removed. `correct_conversation(id, content)` provides the same operation to the agent, requires an actual user-message ID, and accepts only replacement text supplied by the owner. “Delete everything” is not interpreted as a phrase deletion; use the explicit clear-history control.

`update_settings` permits ordinary Jarvis language, pace, timezone, context budget, response length, child mode, news priority and an already downloaded local model. Pydantic validation and post-save verification apply. Credentials, cloud provider, new security access, owner lock and OS settings are not silently changed by this tool. `set_voice` changes installed Jarvis voices. System actions still use the configured, owner-reviewed adapter. Generic MCP server installation/control is not implemented by these changes.

## Live model comparison

Actual hardware: Apple M5 MacBook Pro, 24 GB unified memory, macOS 27.0.1. Native isolated Ollama 0.35.1, 8K context, thinking disabled, temperature 0.3, 400 ordinary response tokens. Discussion mode uses the existing larger generation bound. Synthetic persistent SQLite and real note/memory tools; microphone and TTS disabled for these conversational runs. Timings describe individual observations, not benchmark guarantees.

Qwen3 4B instruct remained the fastest English baseline in the final comparison. Warm ordinary first output ranged approximately 0.42–1.02 seconds; cold first response was 3.05 seconds. Its Hindi/Bengali answers had awkward language. Qwen3.5 4B offered newer multilingual weights but still needed controller safeguards: warm ordinary first output was approximately 0.93–1.32 seconds, with some extra tool-planning requests longer. Qwen3.5 9B and Gemma4 12B were tested before the final cache/deletion corrections and were slower; they also made unsupported memory-action claims. Those earlier measurements are diagnostic runs, not comparable final performance gates. No model was silently selected solely because it was newer.

The official [Qwen3.5 model card](https://huggingface.co/Qwen/Qwen3.5-9B) documents a multilingual family and Apache-2.0 weights. Google's [Gemma4 model card](https://ai.google.dev/gemma/docs/core/model_card_4) documents a fixed training cutoff. Recent release dates do not mean continuous live training. Use versioned model downloads for capability updates, private SQLite recall for personal context, and dated live retrieval for current public facts. Larger Qwen3.6 variants leave little memory headroom for speech/OS on a 24GB machine; they were not selected or performance-tested here.

These are conversation smoke gates, not a blinded human fluency evaluation. Empathy, language naturalness, long-form reasoning and factual accuracy can still vary. Neither affectionate wording nor a vendor benchmark establishes reliability. The owner should evaluate voices by listening and evaluate consequential factual answers against their cited source/tool result.
