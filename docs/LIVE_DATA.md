# Live facts, saved memory and model training

A model's training cutoff does not move when an API is connected. Jarvis does not retrain model weights from conversations. Its automatic local recall retrieves prior **user statements**, separately from current public sources. The controller must not invent the configured provider's cutoff.

For current news/headline questions, Jarvis retrieves the fixed India-first RSS sources before generation. A cache older than 15 minutes triggers a bounded on-demand refresh when news networking is enabled. Failed refreshes retain dated records and disclose failure; offline/stale items are not current evidence. Publication and retrieval times are different: a newly retrieved page can describe an old event. Coverage is selected BBC, Guardian and Indian Express feeds, not every event worldwide. Headlines are summaries, not full-article verification.

For broader public current questions (“Who is the current president of India?”, “What is the latest AI research?”), optional **Google cited search** retrieves before answering. Enable it in Settings after saving your own Gemini key under the Google provider preset. Your conversation model can remain Ollama or Groq. Only the current public question is sent by this automatic search path; saved conversations, mail/calendar and memory are not used as its query. Private/action requests retain their own tools. A failed, disabled or uncited lookup produces an explicit inability to verify current facts, rather than a guess from training. Source links and retrieval times appear below the response. Unknown desktop source hosts need a visible link-opening review.

Routing recognizes explicit English current/news phrases and current office-holder questions. A follow-up without a public topic, or an unrecognized temporal phrase, may need “Search the web for …” with the complete topic. This is not a universal truth verifier. Prefer primary sources; double-check high-stakes facts, publication dates and contradictions. Financial prices/quotes are not supplied by a dedicated live market feed.

The configurable search model defaults to `gemini-3.1-flash-lite`; `gemini-2.5-flash-lite` and `gemini-3.8-flash` are alternative identifiers. The account must support the selected model. The Google adapter uses the official [Interactions REST API](https://ai.google.dev/gemini-api/docs/interactions-overview) with [Google Search grounding](https://ai.google.dev/gemini-api/docs/google-search), `store:false`, HTTPS, header authentication, no redirects and bounded responses. It discards thought steps. Actual citation annotations are required. Provider Search suggestions are rendered in a sandbox without scripts or parent access. `store:false` disables stored interactions; it does **not** override Google's terms, free-tier data-use policies or HTTP service logs.

Jarvis caps search at 10 attempts and speech at 20 attempts per UTC day, including failures. Provider/account quotas are separate. There are no automatic retries, billing setup or purchases. Google lists free tiers for some model/grounding combinations; account availability and current [pricing](https://ai.google.dev/gemini-api/docs/pricing) must be checked. A cap does not guarantee a request is free if your project uses paid billing.

Optional Google speech uses a separate opt-in, the user's same Gemini credential, configurable `google_tts_model` and Kore/Aoede/Puck/Charon. This sends spoken reply text to Google. Local Kokoro Heart remains the offline voice. REST contract tests are mocked; live account synthesis/search is reported separately in verification. No Bengali output or singing is claimed.

For entirely offline use select Ollama and a downloaded local voice, disable news, Google search, hosted voices and update checks. Current external facts cannot be refreshed offline; local conversations, notes, reminders, selected-document search and saved memory remain available.

## Continuous learning boundaries

Automatic conversation recall is enabled by default and retrieves relevant prior user statements without a manual remember command. Recent turns, an extractive summary and bounded retrieved records supply context. This is retrieval, not weight training or perfect recall. An assistant reply is not promoted to a fact about the owner. The Memory interface can inspect, correct and delete stored statements; deletion also invalidates summaries and in-flight context so deleted information is not silently reused. Separate explicit preferences remain editable.

Personal records stay in the individual installation and are never included in public source or release archives. A selected hosted conversation model receives its bounded context; choose Ollama for local inference. News/search records retain source links and dates, separately from personal context. Retrieved content cannot grant tool permissions.

Future model training should use an owner-approved, redacted dataset and isolated candidate model, then pass accuracy, privacy, tool-safety and voice tests before replacing the active model. No automatic chat fine-tuning, self-modifying permissions or untested nightly model replacement is implemented.
